◆ CRCSCAN_CRC32

◆ DIAG_EEPROM_ADDRESS

#define DIAG_EEPROM_ADDRESS   EEPROM_START

Configures the EEPROM address used by NVM parity and EEPROM ECC error injection diagnostics.

This macro is used by T_RunStartupDiagnostics and T_RunNextLatentFaultDiag to provide the EEPROM address passed to MW_DiagNvmParity and MW_DiagNvmEepromEcc.

Note
The default value is the start of EEPROM, which is erased on an unprogrammed device.

MW_DiagNvmParity tolerates this because the default INIT_NVM_ECC_ALL_ONES setting disregards all-ones in EEPROM.

Warning

The EEPROM parity diagnostic may modify the data at this address. The injected parity error is intended to block the write, but a diagnostic failure may allow the write to complete. Reserve this location for diagnostic use.

Warning
This address must point to initialized EEPROM data if DIAG_STARTUP_ECC_EEPROM or

DIAG_PERIODIC_ECC_EEPROM is enabled. Reading erased EEPROM raises an ECC error that the diagnostic cannot distinguish from its own injection, and if INIT_NVM_ECC_ALL_ONES disregards all-ones for EEPROM the error flag is suppressed instead, so the diagnostic reports an error and the injection is left armed. Disregarding all-ones is therefore not a substitute for initializing the data. See MW_DiagNvmEepromEcc for details.

Valid configurations: between EEPROM_START and EEPROM_END, as defined in the device-specific header file.

◆ DIAG_FLASH_ADDRESS

#define DIAG_FLASH_ADDRESS   PROGMEM_START

Configures the Flash address used by Flash ECC error injection diagnostics.

This macro is used by T_RunStartupDiagnostics and T_RunNextLatentFaultDiag to provide the Flash read address passed to MW_DiagNvmFlashEcc.

Note

This is a byte address in the Flash address space, starting at PROGMEM_START. It is not an address in the Flash region mapped into CPU Data Space, and it is therefore unaffected by the Flash section selected by NVMCTRL.CTRLB.FLMAP.

Note

The diagnostic only reads the configured address. The data at this location is not modified.

Note
The default value points to the reset vector, which is typically programmed. An address relocated into APPDATA may be erased without producing an ECC error, since

INIT_NVM_ECC_ALL_ONES defaults to a value that disregards all-ones in that section.

Warning
This address must point to initialized Flash data. Reading erased Flash raises an ECC error that the diagnostic cannot distinguish from its own injection, and if

INIT_NVM_ECC_ALL_ONES disregards all-ones for that section the error flag is suppressed instead, so the diagnostic reports an error and the injection is left armed. Disregarding all-ones is therefore not a substitute for initializing the data. See MW_DiagNvmFlashEcc for details.

Warning

If Flash read protection is enabled (BOOTRP in NVMCTRL.CTRLB), a read of the BOOT section from outside it returns 0x00 instead of the Flash contents, so the diagnostic result cannot be relied on. When the diagnostic executes outside the BOOT section, this address must point to APPCODE or APPDATA. The default value points to the start of Flash, which is inside the BOOT section.

Valid configurations: between PROGMEM_START and PROGMEM_END, as defined in the device-specific header file.

◆ DIAG_PERIODIC_CFD0

#define DIAG_PERIODIC_CFD0   DISABLED

Enables or disables execution of the CFD0 diagnostic in T_RunNextLatentFaultDiag.

This macro configures, at compile-time, whether to include the Clock Failure Detection channel 0 (CFD0) diagnostic in the T_RunNextLatentFaultDiag function. This configuration only ensures that T_RunNextLatentFaultDiag initiates the diagnostic. The end diagnostics are not called as part of the Run Next Latent Fault Diagnostic function and must be scheduled as part of the TM_Scheduler schedule. It is the responsibility of the application to determine when to call the end diagnostic to avoid calling it before the diagnostic is complete.

Warning

This diagnostic temporarily disables the safety mechanism in Mission Mode, potentially masking true faults during execution. It also disables global interrupts during execution, which may delay the servicing of other error-handling interrupts. The global interrupts are only disabled for the duration of the begin or end functions and are restored for the duration between the start and completion of this diagnostic.

Note

This diagnostic is disabled by default since the redundant CFD monitor is enabled by default in INIT_REDUNDANT_CFD.

Valid configurations:

  • ENABLED

This macro configures, at compile-time, whether to execute the CRCSCAN error injection diagnostic in T_EnterIdleSleep before starting a scan of the next Flash section. This diagnostic is not included in the normal startup and periodic diagnostic execution Tasks, because the CRCSCAN in Flash mode is not used as a safety mechanism in Mission Mode by default. Note

T_EnterIdleSleep is called instead.

Warning

If enabled, T_EnterIdleSleep depends on T_HandleCrcInterrupt to handle the CRCSCAN interrupt required to complete the diagnostic.

Warning

This diagnostic may be incompatible with the Boot Section Read Protection (BOOTRP) setting in NVMCTRL. See MW_DiagCrcScan for more details.

Warning

See PERIODIC_CRCSCAN for further information on user requirements, side effects and assumptions for using this feature.

Note

This diagnostic is enabled by default since it is recommended to diagnose the CRCSCAN mechanism if it is in use.

It then uses the SWDT again to wait DUR_UNTIL_SAFE_SHUTDOWN clock cycles before clearing the WWDT a final time, applying the new configuration and proceeding to perform shutdown sleep.

Valid configurations: between 0 and (UINT24_MAX - SWDT_OPEN_WINDOW).

Note
Setting this macro to 0 will not disable the SWDT, but will load a reset value equal to

SWDT_OPEN_WINDOW.

To prevent the WWDT clear from happening inside the closed window or the WWDT from timing out, this macro must be configured so that: 

 t_app + t_align > WWDT closed window,
 t_app + t_align < WWDT total timeout,
 t_align > measured WCET + tolerance,

where t_app is the duration of the application shutdown Task (0 if Task is NULL), t_align is DUR_UNTIL_SAFE_SHUTDOWN, and WCET is the worst-case execution time between starting the SWDT and reaching the point where the SWDT is actually cleared during initialization of the safe shutdown. The WWDT closed window is equal to the configured WWDT_CLOSED_WINDOW and the WWDT total timeout is the sum of the configured WWDT_CLOSED_WINDOW and WWDT_OPEN_WINDOW values.

Note

Window alignment is only required before shutdown is configured. During shutdown, both WDT and SWDT are used without windowed mode.

Default with tolerance assumes an application-specific shutdown Task set to NULL (thus zero duration) and a WWDT_CLOSED_WINDOW set to WDT_TIMEOUT_CLK128 and WWDT_OPEN_WINDOW set to WDT_TIMEOUT_CLK64 with a main clock at 20 MHz. This ensures the WDT is approximately in the middle of its open window.

Configures whether to use Standby or Power-Down sleep mode in TM_Shutdown.

This macro configures, at compile-time, whether T_EnterShutdownSleep enters Power-Down sleep mode instead of the default Standby sleep mode during shutdown.

Power-Down typically provides lower power consumption than Standby by disabling more clock domains and peripherals in sleep. However, this can also impact which wake-up sources are available. See the device data sheet for more information.

Note

A suitable wake-up source must be configured by the application before entering shutdown sleep. If no wake-up source is enabled, the device will not wake up. Ensure the selected wake-up source(s) are compatible with the selected sleep mode and peripheral configuration.

Warning
Most hardware safety mechanisms are inactive in deep sleep modes. It is recommended to enter a Safe State before shutdown sleep and restart the device to exit shutdown. See

SHUTDOWN_SAFE_STATE and T_InitSafeShutdown for more information.

Note
To reduce power consumption further, see INIT_VMON_ALWAYS_ON and

INIT_VMON_FULL_POWER_MODE settings as well as Tips and Tricks for information on disabling the Brown-out Detector (BOD) and Watchdog Timer (WDT) Clock Monitor.

Valid configurations:

  • ENABLED
  • DISABLED

◆ SHUTDOWN_SAFE_STATE

#define SHUTDOWN_SAFE_STATE   ENABLED

Enables or disables entering a Safe State in T_InitSafeShutdown before shutdown sleep.

This macro configures, at compile-time, whether T_InitSafeShutdown enters a Safe State by force floating (tri-stating) all I/O pins before entering shutdown sleep. This ensures that sleep can be safely entered, since several hardware safety mechanisms are inactive in deep sleep modes.

Warning

If the application requires an I/O pin to keep driving an output during shutdown sleep, such as a PWM signal, this setting can be disabled. It will then be the responsibility of the application to ensure safe operation before entering sleep. It is recommended to manually tri-state all other I/O pins in the application-specific shutdown Task passed to TM_Shutdown. See Tips and Tricks for more information.

Warning

If Safe State entry fails, ERRID_SAFE_IO is reported to the Error Handler. It is recommended to abort shutdown entry by performing a device reset if this occurs.

Valid configurations:

  • ENABLED
  • DISABLED

◆ SHUTDOWN_SUSPEND_CFD_CFM

#define SHUTDOWN_SUSPEND_CFD_CFM   ENABLED

Enables or disables suspending clock monitors before shutdown sleep in TM_Shutdown.

This macro configures, at compile-time, whether T_InitSafeShutdown stops the clock monitors CFM0, CFM1, CFD0 and CFD1 before entering shutdown sleep. Clock monitors can be impacted by sleep entry and exit depending on the monitored clock sources, and may report spurious errors when the device wakes up. When enabled, all of these monitors are stopped to prevent such error reporting during shutdown.

If the application requires specific clock monitoring during shutdown wake-ups, this setting should be disabled. In such cases, only clock sources that remain stable during sleep entry and wake-up should be monitored, and the application must instead stop or reconfigure the relevant monitors in the application-specific shutdown Task passed to TM_Shutdown.

Note

Whether a clock source being monitored is affected by sleep depends on the selected sleep mode. See SHUTDOWN_POWER_DOWN for configuration of the shutdown sleep mode.

Note

This setting affects all CFM and CFD monitors, regardless of how they were configured during initialization. Both CFM0 and CFD0 are configured to monitor the main clock at startup by default, while CFM1 and CFD1 may either be configured for redundant monitoring or configured by the application. See INIT_REDUNDANT_CFD, INIT_CFM0_WIN_REF and INIT_REDUNDANT_CFM.

Valid configurations:

  • ENABLED
  • DISABLED

◆ SHUTDOWN_WDT_DURATION

#define SHUTDOWN_WDT_DURATION   WDT_TIMEOUT_CLK8K

Configures the Watchdog Timer (WDT) timeout used during sleep in TM_Shutdown.

This macro configures the WDT timeout used during shutdown after T_InitSafeShutdown reconfigures the WDT to operate without windowed mode. The configured timeout is applied when the WDT is cleared in the Shutdown sequence, after which the WDT can be cleared at any time when the device wakes up.

The WDT provides a fallback recovery mechanism during shutdown by timing out if the device fails to wake up or if the shutdown loop fails to re-enter sleep as expected. Since the system has already transitioned into a Safe State, a more relaxed WDT configuration can be used compared to Mission Mode, which reduces the required wake-up frequency and removes the need for strict WDT clear timing.

Note

The WDT must be periodically serviced by calling TM_ShutdownRequestWatchdogs while the device is awake before it expires. This is typically done from a wake-up interrupt handler. See Tips and Tricks for guidance on suitable handling strategies for different scenarios.

Note

The Synchronous Watchdog Timer (SWDT) halts counting while the device is in sleep, but will resume counting each time the device wakes up. The SWDT is therefore configured to always operate in its open window during shutdown and is cleared together with the WDT.

Warning
If SHUTDOWN_CRCSCAN is enabled, the selected timeout must be long enough to reach the first WDT clear performed in the shutdown loop. If required, the application can request a Watchdog clear before the first Standby or Power-Down sleep entry by calling

TM_ShutdownRequestWatchdogs, for instance from the application-specific shutdown Task passed to TM_Shutdown.

Valid configurations: see wdtTimeout_t.

Warning
Setting this macro to WDT_TIMEOUT_OFF disables the WDT during shutdown. This allows maximum power saving in sleep while eliminating the need for periodic wake-ups, but removes the WDT fallback recovery mechanism. An external reset source through the reset pin is highly recommended in this configuration. If the application requires the WDT to be disabled, but still performs occasional wake-ups without calling TM_ShutdownRequestWatchdogs, the SWDT can effectively be disabled in the application-specific shutdown Task as described in Tips and Tricks.

◆ STRICT_SAFE_STATE

#define STRICT_SAFE_STATE   DISABLED

Configures whether to use a strict Safe State to Mission Mode transition in TM_PreStartup and TM_Startup.

This macro configures, at compile-time, whether to enable the Strict Safe State mode in the T_EnsureSafeState Task. If enabled, all I/O-pins are force floated (tri-stated) at the beginning of the pre-startup sequence of TM_PreStartup. This ensures that the system maintains a strict Safe State even if application tasks, in the TM_Startup schedule, initializes peripherals and I/O-pins before officially entering Mission Mode. The T_StartMissionMode Task is responsible for disabling force-float after running the Startup schedule, to have a strict transition from Safe State to Mission Mode.

Warning

Depending on the peripheral and PORT configuration on the device, as well as the surrounding circuitry, disabling force floating of all I/O-pins simultaneously might result in a power surge. For this reason, this feature is disabled by default and should be thoroughly tested for the specific application when enabled.

Valid configurations:

  • ENABLED
  • DISABLED

◆ SWDT_OPEN_WINDOW

#define SWDT_OPEN_WINDOW   500U

Configures the open window size used for the Synchronous Watchdog (SWDT).

This macro is used by T_InitSafetySystem and configures the open window used for the SWDT. The configured value allocates the number of clock cycles at the end of the total duration of the SWDT period where it is allowed to send a clear command. The T_HandleSyncWatchdog task, responsible for clearing the SWDT, will wait until reaching the open window before clearing immediately. For this reason, it treats the closed window period as the real SWDT timeout and thus assumes that the open window is configured to a small value.

Valid configurations: between 1 and UINT16_MAX.

  • Maximum measured execution time for T_HandleSyncWatchdog when already in the open window (rounded up): 350 cycles
  • Default with tolerance: 500 cycles

◆ WWDT_CLOSED_WINDOW

#define WWDT_CLOSED_WINDOW   WDT_TIMEOUT_CLK128

Configures the Windowed Watchdog Timer (WWDT) closed window duration in Mission Mode.

This macro, together with WWDT_OPEN_WINDOW, is used to set the total timeout period of the WWDT in T_StartMissionMode. The timeout is intended to be configured equal to or smaller than the device Fault Detection Time Interval (FDTI), accounting for WDT clock tolerances.

The closed window is the period in which the watchdog cannot be cleared. A premature clear attempt will result in a hardware error. For this reason, it is recommended to set the closed window to a much larger value than the open window, within the limitations of the WDT granularity settings, to ensure clearing is only done at the end of the period. See the watchdog sections in Tips and Tricks for methods to increase the effective granularity and length of the WWDT timeout.

It is necessary to consider the duration of the total application schedule in addition to the time it takes from one schedule ending to the next one starting when configuring the closed window as TM_Scheduler will always try to clear the WDT before executing any scheduled tasks. If the WWDT is still in a closed window when calling TM_Scheduler it will result in a hardware error.

Valid configurations: see wdtTimeout_t.

Warning

Setting this macro to WDT_TIMEOUT_OFF will result in configuring the Watchdog Timer (WDT) to run in Normal mode instead of Window mode. This is not recommended, except during development.

Note
The default value in combination with the default value of WWDT_OPEN_WINDOW will result in an FDTI of slightly shorter than 6ms (3.91 ms closed + 1.95 ms open) with a variation in accordance with the tolerances of the OSC32K. Refer to the device datasheet for more details.

◆ resetReasonCallback

const rstCallback_t resetReasonCallback = &T_ResetReasonExampleCallback

Configures the user-configurable callback function used for application specific reset handling in T_HandleResetReason.

This callback setting is configured in the tasks_config.c file and should be set to point to a function with a rstCallback_t type signature in order to implement application-specific handling of the identified device reset reason.

The callback passes a resetInfo_t input parameter, which is a structure containing the reset reason determined in T_DetermineResetReason and an Error ID. The values are validated in T_HandleResetReason before the callback is called. The Error ID is set to ERRID_NONE as long as the Reset Reason is not a software reset. If a software reset has occurred, the Error ID is set to the value stored by EH_InitiateSafeState before issuing the software reset.

Valid configuration: Only functions with the rstCallback_t type signature.

Warning
Setting this to NULL is not a valid configuration.
