Detailed Description

Contains API prototypes for the Power Manager.

The Power Manager provides services to Tasks to ensure correct interaction with features of the SLPCTRL and BODCTRL peripherals.

◆ MW_DiagVmonOverBegin()

errFlag_t MW_DiagVmonOverBegin ( void )

Starts error injection diagnostic to detect faults in the VMON overvoltage detector.

This function starts a VMON overvoltage error injection diagnostic. The diagnostic must be completed by calling MW_DiagVmonOverEnd after MW_IsDiagVmonOverDone returns true. Because the error injection mechanism operates at a relatively slow speed (typically tens of microseconds or more), and its execution time can vary between devices and operating conditions, the diagnostic is designed to run asynchronously, independent of the CPU until completion.

Warning

It is assumed that this diagnostic is run before transitioning the device out of Safe State. It is also possible to use it outside of the Safe State, but such use requires that it is evaluated on a case by case basis whether or not it is safe for the application to inject an error into the voltage regulator while the device is not in a Safe State.

Warning

This diagnostic requires the voltage regulator to be in maximum performance mode. See the device data sheet for more information.

Warning
During diagnostic execution, the VREGFAIL and VREGWARN error channels are set to NOTIFICATION severity. These settings are restored to their original configurations when

MW_DiagVmonOverEnd is called.

Note

This function disables global interrupts during its execution to ensure atomic execution and that accidental interrupts are not triggered by initiating the error injection.

Note

This diagnostic can be used in 'polling mode' or 'interrupt mode'. If the Status Register (SREG) Global Interrupt Enable bit is set, it is assumed that the diagnostic will be finished through an interrupt. However if the Global Interrupt Enable bit is not set, it is assumed that the MW_IsDiagVmonOverDone is called repeatedly to check if the error injection is finished.

Note

The error injection will not be initiated if the Error Controller is not in NORMAL state, if the VREGWARN or VREGFAIL error channels are already set, or if another VMON diagnostic is already ongoing. The diagnostic will also verify if error injection started as expected and return ERROR if it was unsuccessful in transitioning into diagnostic mode.

Return values
ERRORDiagnostic failed to start due to illegal conditions or the diagnostic mode transition failed.
NO_ERRORDiagnostic successfully started.

◆ MW_DiagVmonOverEnd()

errFlag_t MW_DiagVmonOverEnd ( void )

Completes error injection diagnostic to detect faults in the VMON overvoltage detector.

This function completes the diagnostic by checking the result of the error injection started by MW_DiagVmonOverBegin. It evaluates the results of the diagnostic and restores the original configurations of the VREGFAIL and VREGWARN error channels. It should be called after MW_IsDiagVmonOverDone returns true, indicating that the diagnostic has completed.

Note

This function disables global interrupts during its execution to ensure atomic execution and that accidental interrupts are not triggered by finishing the error injection.

Note

If this function is called without having called MW_DiagVmonOverBegin beforehand, it will do nothing and return ERROR in order to avoid data hazards in regards to modifying the VREGFAIL and VREGWARN error channel configurations.

Return values
ERRORFault detected in the VMON overvoltage detector or inappropriate function call.
NO_ERRORNo fault detected in the VMON overvoltage detector.

◆ MW_EnterSleepMode()

errFlag_t MW_EnterSleepMode ( sleepMode_t mode)

Enters the selected device sleep mode.

This function configures the device to use the provided sleep mode, enables sleep, and enters the selected mode by issuing the SLEEP instruction. The device remains in sleep until an interrupt request (IRQ) from an enabled wake-up source occurs, after which execution resumes following the wake-up time associated with the selected sleep mode.

Idle Sleep Mode: The CPU clock is stopped, while all enabled peripherals continue running.

Standby Sleep Mode: The CPU and most clocks are stopped. Certain peripherals can be configured to run in Standby by enabling their RUNSTDBY setting.

Power-Down Sleep Mode: Most high-frequency clocks are stopped. Only low-power peripherals such as the Watchdog Timer (WDT) and the RTC PIT remain active.

Note

Individual peripherals may require additional configuration to operate as intended in the selected sleep mode. Refer to the device data sheet for the sleep behavior of each peripheral.

Note

For detailed information on wake-up times and wake-up sources for each sleep mode, see the device data sheet.

Warning

When enabled, the Synchronous Watchdog Timer (SWDT) is halted during all sleep modes and resumes after wake-up.

Warning

In Standby and Power-Down sleep modes, several safety mechanisms are inactive. It is recommended that the application enter a Safe State before using these modes.

Warning

Several clock sources stop when entering sleep. If the Clock Frequency Monitor (CFM) or Clock Failure Detector (CFD) monitors a clock source that stops in the selected sleep mode, a CFM or CFD event will occur. Disable monitoring before entering sleep and re-enable it after wake-up once the oscillator is stable.

Warning

Configure the Voltage Monitor (VMON) to the desired mode using MW_SetVmonSleep before entering Standby or Power-Down sleep modes.

Warning

If global interrupts are disabled, the SLEEP instruction is ignored and the Sleep Error status bit is automatically set. Check and clear this condition using MW_GetClearSleepError.

Warning

Ensure that at least one valid interrupt wake-up source is enabled before entering sleep. Without a wake-up source, the device will not resume execution except through a device reset.

Parameters
modeThe sleep mode to use when entering device sleep.
Return values
ERRORInvalid sleep mode, sleep entry aborted.
NO_ERRORValid sleep mode, sleep entry attempted.

bool MW_IsDiagVmonOngoing ( void )

Checks whether a VMON error injection diagnostic is ongoing.

This function returns whether a VMON overvoltage or undervoltage error injection diagnostic has been started and not yet ended. It is intended to be used when the diagnostic completion relies on interrupts, allowing the Application to detect if the expected interrupt never occurs and the VMON remains in diagnostic mode.

Return values

falseNo VMON error injection diagnostic is active.

◆ MW_IsDiagVmonOverDone()

bool MW_IsDiagVmonOverDone ( void )

Checks if the VMON overvoltage error injection has been completed.

This function checks the status of the VMON overvoltage error injection to determine whether the diagnostic can be completed. This is done by checking if the error injection was started in the first place, and then if the result is ready for evaluation by MW_DiagVmonOverEnd, indicating that the error injection has finished, either because the injected error was detected by the VMON or because the VMON diagnostic timer timed out.

Note

The error injection diagnostic is initiated by calling MW_DiagVmonOverBegin and is completed by calling MW_DiagVmonOverEnd.

Note

This function should be called periodically after MW_DiagVmonOverBegin to poll the status of the diagnostic or used in an interrupt to check if the diagnostic is ready to be completed.

Note

If the diagnostic was never started, this function always returns false. To determine whether a VMON error injection diagnostic is active, use MW_IsDiagVmonOngoing.

Return values
trueThe VMON overvoltage error injection is finished and ready for evaluation.
falseThe error injection is not finished or was never started.

◆ MW_SetVmonSleep()

void MW_SetVmonSleep ( bool enableInSleep,
bool useFullPowerMode )

Configures Voltage Monitor (VMON) operation during Standby or Power-Down sleep.

Note

If Full Power Mode is used, the VMON will always be in maximum performance regardless of main clock source and sleep modes. This will also ensure a shorter wake up time from Standby or Power-Down sleep. Otherwise, Auto Mode is used, which automatically changes performance based on device state.

Parameters
enableInSleepConfigures whether or not the VMON is enabled in Standby or Power-Down sleep.
useFullPowerModeConfigures whether the VMON uses Full Power Mode or Auto Mode.
Note
If VMON is disabled in sleep, the VDIS (VMON Disabled) flag may be set on entering sleep. If Auto Mode is used, entering Standby or Power-Down sleep may set the VSLP (VMON Sleep Entry) flag. Both flags remain set after wake-up and can be checked and cleared by

MW_GetClearVmonDisabledError and MW_GetClearVmonSleepEntryError respectively.
