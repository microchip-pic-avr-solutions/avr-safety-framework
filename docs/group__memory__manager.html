Detailed Description

Contains API prototypes for the Memory Manager.

The Memory Manager provides services to Tasks to ensure correct interaction with features of the RAMCTRL, NVMCTRL, CPU and GPR peripherals.

Enumeration Type Documentation

◆ eccAllOnes_t

enum eccAllOnes_t

Type defines for available "ECC all ones" (ECCALL1) options.

When this feature is enabled for a memory section, it disregards the ECC check on Non-volatile Memory words read as all 1's from that section. This prevents false ECC errors when the application reads erased memory.

Note

These available configurations are only applicable for Non-volatile Memory and does not affect RAM.

Note
No option covers both the code Flash sections and EEPROM. EEPROM is only covered by

ECC_ALL_ONES_APPDATA_EEPROM, which in turn excludes APPCODE and BOOT.

Warning
Enabling this feature for a section that an NVM ECC diagnostic reads while that section is uninitialized causes the diagnostic to report an error and leaves an error injection armed. See MW_DiagNvmFlashEcc and MW_DiagNvmEepromEcc.
Enumerator
ECC_ALL_ONES_NONE 

ECC all-ones feature disabled for all Non-volatile Memory.

ECC_ALL_ONES_ALL_FLASH 

ECC all-ones feature enabled for BOOT, APPCODE, APPDATA, USERROW and BOOTROW.

ECC_ALL_ONES_USER_DATA 

ECC all-ones feature enabled for APPDATA and USERROW.

ECC_ALL_ONES_APPDATA_EEPROM 

ECC all-ones feature enabled for EEPROM, APPDATA, USERROW, and BOOTROW.

ECC_ALL_ONES_MAX 

Reserved or invalid sentinel value for the ECC all-ones configuration.

◆ persistentFlag_t

enum persistentFlag_t

Enum for persistent flags used to store data between non-POR/BOR device resets.

Several diagnostics triggers a reset of the device to verify the functionality of a safety mechanism. These flags are used to store data between resets and indicate if diagnostics are ongoing or if a fault has occurred. The flags are written to General Purpose Registers (GPR) and are stored redundantly, meaning each flag consists of two bits stored in two different locations.

Note
All flags will default to false after a Power On Reset (POR) or Brownout Reset (BOR).
Enumerator
PFLAG_ERRINJ_ONGOING 

Stores if an error injection leading to reset is ongoing

PFLAG_CPU_INJ_FAULT 

Stores if a CPU Lockstep error injection fault detected

PFLAG_WDT_INJ_FAULT 

Stores if a WDT Expire error injection fault detected

PFLAG_SWDT_INJ_FAULT 

Stores if a SWDT Expire error injection fault detected

PFLAG_IO_FLOAT_FAULT 

Stores if the device was not in a Safe State after reset

PFLAG_MAX 

Reserved/invalid, used as sentinel value for persistent flag.

◆ persistentVal_t

enum persistentVal_t

Enum for persistent values used to store data between non-POR/BOR device resets.

Whenever the device is reset, it may be necessary to determine the cause of the reset initiated by software. These values are used to store data between resets and indicate the reason for the reset and any associated Error ID or Error Injection reason. The persistent value types are used to write data to and read data from specific locations in the General Purpose registers (GPR). A checksum is always calculated when storing a value and can be verified when reading from these locations.

Note
All persistent values will default to zero after a Power On Reset (POR) or Brownout Reset (BOR).
Warning
Each persistent value type has a fixed size, and its max value is determined by the highest value of the type of reason to be stored.
Enumerator
PVAL_ERRID_REASON 

Stores an 8-bit value corresponding to an Error ID

PVAL_RESET_REASON 

Stores a 6-bit value corresponding to a Reset Reason

PVAL_ERRINJ_REASON 

Stores a 2-bit value corresponding to an Error Injection Reset Reason

PVAL_MAX 

Reserved/invalid, used as sentinel value for persistent value.

◆ ASM_InjectCpuDataParityNvm()

void ASM_InjectCpuDataParityNvm ( uint16_t eepromDiagAddr)

This function makes the CPU inject a parity error in the data of the following NVM (EEPROM) write, which is detected by the NVM data Parity Checker.

Warning

This error injection assumes that neither EEBUSY nor FBUSY is set and does not wait for the NVM controller to become available. The caller must verify that the NVM controller is ready before calling this function.

Warning

This error injection assumes that EEPROM is not busy and will not wait for it to become available (and potentially get stuck). It is up to the caller to verify that the EEPROM is ready to accept write instructions.

Warning

This error injection does not restore the stored EEPROM value after injecting an error preventing the application to use this address. The parity safety mechanism should prevent any corrupted data to be written to EEPROM. If the safety mechanism fails the corrupted data will be written to the address giving two unwanted scenarios:

  • The device could reset during the diagnostic leading to loss of customer data.
  • Doing two EEPROM writes means waiting for the EEPROM to be ready before restoring.

Parameters
eepromDiagAddrAn address to data in EEPROM, used to trigger the EEPROM write instruction.

◆ ASM_InjectRamEcc1()

void ASM_InjectRamEcc1 ( uint16_t ramDiagAddr)

This function makes the RAM controller inject a 1-bit ECC error in the following RAM read, which is detected by the RAM ECC Checker.

Warning

This function injects an actual ECC error at the provided address, meaning the address must not point to application data. The function reads from 4 bytes ahead of the provided address to flush the RAM buffer (when present in devices with 32-bit RAM ECC granularity), ensuring the corrupted data is written to physical RAM. Therefore, the provided address must have at least 4 bytes of valid allocated memory following it. Additionally, due to RAM buffer alignment, the 3 bytes preceding the provided address must also be reserved, as they may reside within the same RAM double word as the injection point. These requirements can be achieved by reserving an array of at least 8 bytes where the address points to an index at least 3 from the start of it and 4 from the end.

Parameters
ramDiagAddrAn address to data in RAM, used to inject ECC error.

◆ ASM_TriggerEepromEcc()

void ASM_TriggerEepromEcc ( uint16_t eepromDiagAddr)

This function performs a read from the provided EEPROM address to trigger ECC error detection after an ECC error has been injected via NVMCTRL.CTRLD.

The NVMCTRL ECC injection mechanism requires a data read from NVM to trigger detection. This function performs that read using assembly, ensuring that the instruction is not optimized away by the compiler.

Note

EEPROM is accessed through CPU Data Space, so this address is a Data Space address. This differs from ASM_TriggerFlashEcc, which takes an address in the Flash address space.

Note

The read result is intentionally discarded. The purpose of the read is solely to trigger the ECC detection mechanism.

Parameters
eepromDiagAddrAn address to data in EEPROM in CPU Data Space, used to trigger ECC error detection.

◆ ASM_TriggerFlashEcc()

void ASM_TriggerFlashEcc ( uint16_t flashDiagAddr)

This function performs a read from the provided Flash address to trigger ECC error detection after an ECC error has been injected via NVMCTRL.CTRLD.

The NVMCTRL ECC injection mechanism requires a data read from NVM to trigger detection. This function performs that read using the LPM instruction in assembly, ensuring that the instruction is not optimized away by the compiler. An instruction fetch does not consume the injected error, so the injection remains armed until this read is performed.

Note

LPM addresses the Flash directly in the Flash address space rather than through the Flash region mapped into CPU Data Space. The trigger is therefore unaffected by the Flash section selected by NVMCTRL.CTRLB.FLMAP.

Note

The read result is intentionally discarded. The purpose of the read is solely to trigger the ECC detection mechanism.

Parameters
flashDiagAddrA byte address to data in Flash, used to trigger ECC error detection.

◆ MW_DiagNvmEepromEcc()

errFlag_t MW_DiagNvmEepromEcc ( uint16_t eepromDiagAddr)

This function performs error injection diagnostic to detect faults in the NVMCTRL ECC checkers with EEPROM read trigger.

The diagnostic starts by disabling global and non-maskable interrupts. This is done to prevent the interrupt routines from triggering and reporting actual errors. The error channels that will trigger due to the diagnostic are configured by disabling float and setting the severity to NOTIFICATION.

Warning

Before starting the error injection sequence, the function verifies that the NVM is not busy. If the EEBUSY or FBUSY flag in NVMCTRL.STATUS is set, no ECC injection is started and the function returns ERROR. This prevents the diagnostic from starting while the NVM controller reports Flash or EEPROM busy.

The diagnostic runs injection tests on the NVM ECC checkers using EEPROM as the trigger. The injection tests are done by setting the injection bit for the specific checker in the correct control register before performing an instruction that triggers that checker.

This diagnostic does the following error injection tests:

  • 1-bit error injection on EEPROM, triggered by EEPROM read.
  • 2-bit error injection on EEPROM, triggered by EEPROM read.

Note

The 2-bit error injection will trigger the Bus error channel.

Note

This diagnostic does not test the ECC comparator as that is covered in full by MW_DiagNvmFlashEcc.

After the ECC1 and ECC2 injections, the diagnostic verifies the error was correctly detected by checking interrupt flags and error channels. The reported error address is verified against the configured EEPROM address. For the ECC1 injection, it also verifies that the reported ECC syndrome matches the expected value, before clearing the interrupt flags and error channels.

After clearing the interrupts and error channels, the diagnostic restores the global interrupt state, enables NMI, and restores the error channels used to their original configuration.

Warning

NMI is expected to be enabled by default. If NMI is intentionally kept disabled, it must be disabled again after the diagnostic completes.

Warning

This diagnostic temporarily disables the safety mechanism (EEPROM and BUSERR error channels) when called in Mission Mode, potentially masking true faults during execution. It also disables global interrupt during execution, which may delay the servicing of other error-handling interrupts. The original configuration is restored when the diagnostic is complete.

Note

Error injection will not be initiated if the Error Controller is not in NORMAL state or the EEPROM or BUSERR error channels is already set. If either of these conditions occur, the diagnostic function will return an error indicating that the error injection process could not be started.

Warning

This diagnostic is redundant as the NVM controller shares the ECC checkers between Flash and EEPROM. Therefore, the MW_DiagNvmFlashEcc diagnostic is sufficient to achieve full coverage of the NVM ECC checker. This diagnostic is included to enable testing the full error chain by injecting an error in the EEPROM and verifying that it triggers the correct error channel. Additionally, error channel diagnostics are available to ensure that the EEPROM error channel functions as expected without the need to inject any errors into the EEPROM itself.

Parameters
eepromDiagAddrA valid EEPROM address, pointing to initialized data. Used to trigger EEPROM reads during NVM ECC diagnostics.
Note

This diagnostic only reads from the EEPROM address. The data at this location is not modified.

Warning
The configured address must contain initialized data. Reading erased EEPROM raises an ECC error the diagnostic cannot distinguish from its own injection, and if the

eccAllOnes_t configuration disregards all 1's for EEPROM the ECC error flag is suppressed instead. The diagnostic then reports an error, and because the injection is cleared only when an ECC 1-bit or 2-bit flag is detected, it remains armed and is applied to the next Non-volatile Memory access that raises a flag. Only the ECC check bits are injected, so stored data is not altered, but the error is reported far from its cause.

Return values
ERRORFault detected in the NVMCTRL ECC1 or ECC2 error detection mechanisms, reported address or syndrome did not match the expected value, eepromDiagAddr was invalid, the diagnostic did not start, or NVM was busy.
NO_ERRORNo fault detected in the redundant NVMCTRL ECC checkers.

◆ MW_DiagNvmFlashEcc()

errFlag_t MW_DiagNvmFlashEcc ( uint16_t flashDiagAddr)

This function performs error injection diagnostic to detect faults in the NVMCTRL ECC checkers with Flash read trigger.

The diagnostic starts by disabling global and non-maskable interrupts. This is done to prevent the interrupt routines from triggering and reporting actual errors. The error channels that will trigger due to the diagnostic are configured by disabling float and setting the severity to NOTIFICATION.

Warning

Before starting the error injection sequence, the function verifies that the NVM is not busy. If the EEBUSY or FBUSY flag in NVMCTRL.STATUS is set, no ECC injection is started and the function returns ERROR. This prevents the diagnostic from starting while the NVM controller reports Flash or EEPROM busy.

The diagnostic runs injection tests on the NVM ECC checkers using Flash as the trigger. The injection tests are done by setting the injection bit for the specific checker in the correct control register before performing an instruction that triggers that checker.

This diagnostic does the following error injection tests:

  • Error injection on NVM ECC comparator, triggered by Flash read.
  • 1-bit error injection on Flash, triggered by Flash read.
  • 2-bit error injection on Flash, triggered by Flash read.

Note

The 2-bit error injection will trigger the Bus error channel.

After the ECC1 and ECC2 injections, the diagnostic verifies the error was correctly detected by checking interrupt flags and error channels. The reported error address is verified against the configured Flash address. For the ECC1 injection, it also verifies that the reported ECC syndrome matches the expected value, before clearing the interrupt flags and error channels.

After clearing the interrupts and error channels, the diagnostic restores the global interrupt state, enables NMI, and restores the error channels used to their original configuration.

Warning

NMI is expected to be enabled by default. If NMI is intentionally kept disabled, it must be disabled again after the diagnostic completes.

Warning

This diagnostic temporarily disables the safety mechanism (FLASH1, FLASH2 and BUSERR error channels) when called in Mission Mode, potentially masking true faults during execution. It also disables global interrupt during execution, which may delay the servicing of other error-handling interrupts. The original configuration is restored when the diagnostic is complete.

Note

Error injection will not be initiated if the Error Controller is not in NORMAL state or the FLASH1, FLASH2 or BUSERR error channels is already set. If either of these conditions occur, the diagnostic function will return an error indicating that the error injection process could not be started.

Parameters
flashDiagAddrA valid byte address in the Flash address space, starting at PROGMEM_START, pointing to initialized data. Used to trigger Flash reads during NVM ECC diagnostics.
Note

This diagnostic only reads from the Flash address. The data at this location is not modified.

Note

The address is a Flash address as used by the LPM instruction. It is not an address in the Flash region mapped into CPU Data Space, so it is unaffected by the Flash section selected by NVMCTRL.CTRLB.FLMAP.

Warning

The configured address must contain initialized data. Reading erased Flash returns all 1's in both the data and the ECC bits, which normally raises an ECC error the diagnostic cannot distinguish from its own injection. If the eccAllOnes_t configuration disregards all 1's for that section, the ECC error flag is suppressed instead. The diagnostic then reports an error, and because the injection is cleared only when an ECC 1-bit or 2-bit flag is detected, it remains armed and is applied to the next Non-volatile Memory access that raises a flag. That access is unrelated to the diagnostic, at an unpredictable address and time. Only the ECC check bits are injected, so stored data is not altered, but the error is reported far from its cause.

Warning

If Flash read protection is enabled (BOOTRP in NVMCTRL.CTRLB), a read of the BOOT section from outside it returns 0x00 instead of the Flash contents, so the diagnostic result cannot be relied on. When this function executes outside the BOOT section, the address must point to APPCODE or APPDATA. The default address is inside the BOOT section.

Return values
ERRORFault detected in the NVMCTRL ECC error detection mechanisms, reported address or syndrome did not match the expected value, flashDiagAddr was invalid, the diagnostic did not start, or NVM was busy.
NO_ERRORNo fault detected in the redundant NVMCTRL ECC checkers.

errFlag_t MW_DiagNvmParity ( uint16_t eepromDiagAddr)

This function performs error injection diagnostic to detect faults in the CPU and NVM bus parity checkers triggered by NVM access.

The diagnostic starts by disabling global and non-maskable interrupts. This is done to prevent the interrupt routines from triggering and reporting actual errors. The error channels that will trigger due to the diagnostic are configured by disabling float and setting the severity to NOTIFICATION.

Warning

Before starting the error injection sequence, the function verifies that the NVM is not busy. If the EEBUSY or FBUSY flag in NVMCTRL.STATUS is set, no parity injection is started and the function returns ERROR. This prevents the diagnostic from starting while the NVM controller reports Flash or EEPROM busy.

The diagnostic runs several injection test on different NVM and CPU parity checkers on the device. The injection tests are done by setting the injection bit for the specific checker in the correct control register before performing an instruction that triggers that checker. To make sure that the trigger instruction is known, and not a random instruction, the injection and trigger actions are done using assembly functions.

This diagnostic does the following error injection tests:

  • Error injection on NVM data parity generator, triggered by NVM read.
  • Error injection on NVM instruction parity generator, triggered by NVM fetch.
  • Error injection on CPU data parity generator, triggered by NVM write.
  • Error injection on CPU address parity generator, triggered by NVM read.
  • Error injection on CPU control parity generator, triggered by NVM read.

The interrupt flags and error channels are cleared after the injection tests have been completed. This is done regardless of whether the tests succeeded or failed.

After clearing the interrupts and error channels, the diagnostic restores the global interrupt state, enables NMI, and restores the error channels used to their original configuration.

Warning

NMI is expected to be enabled by default. If NMI is intentionally kept disabled, it must be disabled again after the diagnostic completes.

Warning

This diagnostic temporarily disables the safety mechanism (BUSERR and OPC error channels) when called in Mission Mode, potentially masking true faults during execution. It also disables global interrupt during execution, which may delay the servicing of other error-handling interrupts. The original configuration is restored when the diagnostic is complete.

Note

Error injection will not be initiated if the Error Controller is not in NORMAL state or the BUSERR or OPC error channels is already set. If either of these conditions occur, the diagnostic function will return an error indicating that the error injection process could not be started.

Note

NVM write is done on EEPROM to avoid writing to Flash. This also means that the CPU does not halt for the duration of the write as would be the case for Flash. If the error is detected, the write is automatically aborted. However, if not detected, the write will complete. For this reason the EEPROM address passed to this diagnostic must be reserved for diagnostic use.

Parameters
eepromDiagAddrA valid EEPROM address, reserved for diagnostic use, pointing to initialized data. Used for NVM read/write during NVM Parity diagnostics.
Warning

EEPROM address must point to valid, initialized data and must be exclusively reserved for diagnostic use. The diagnostic may modify the data at this address if the parity safety mechanism fails to abort the write (see ASM_InjectCpuDataParityNvm). The application must not rely on preserving the value stored at this location.

Warning

If the EEPROM address points to uninitialized data (all 0xFF in both data and ECC), reading it may cause a 2-bit ECC error regardless of whether error injection succeeded, giving a false positive. The address must contain initialized data, unless all-ones data is configured not to trigger an ECC error.

Return values
ERRORFault detected in the CPU or NVM bus parity checkers, eepromDiagAddr was invalid, the diagnostic did not start, or NVM was busy.
NO_ERRORNo fault detected in the CPU or NVM bus parity checkers.

  • 1-bit error injection on RAM, triggered by RAM read.

The reported error address is verified against the reserved diagnostic array. For the ECC1 injection, it also verifies that the reported ECC syndrome matches the expected value, before clearing the interrupt flags and error channels.

After clearing the interrupts and error channels, the diagnostic restores the global interrupt state, enables NMI, and restores the error channels used to their original configuration.

Warning

NMI is expected to be enabled by default. If NMI is intentionally kept disabled, it must be disabled again after the diagnostic completes.

It also disables global interrupt during execution, which may delay the servicing of other error-handling interrupts. The original configuration is restored when the diagnostic is complete.

Note

Error injection will not be initiated if the Error Controller is not in NORMAL state or the RAM1, RAM2, or BUSERR error channels is already set. If either of these conditions occur, the diagnostic function will return an error indicating that the error injection process could not be started.

◆ MW_IsPersistentFlagsCorrupt()

bool MW_IsPersistentFlagsCorrupt ( void )

Compares two redundant bits for each boolean flags in General Purpose Registers (GPR) and checks if any of the flags are corrupted.

This function reads both bits of a flag and compare their value. If both bits of a flag are zero, the flag is false. If both bits of the flag is one, the flag is true. If the two bits of a flag differ (one is zero and the other is one), the flag is considered corrupt due to a bit-flip or other issue. If any flag is found to be corrupt, it is assumed that all flags are corrupt. This is because the integrity of the operations to reset and write to the flags cannot be trusted if any data is corrupted. Additionally, this function checks whether the invalid input flag has been set or not.

Return values
trueOne or more flags have been corrupted, or invalid input flag is set.
falseNo flag corruption detected.

Checks if any of the stored persistent values are corrupted.

◆ MW_StorePersistentVal()

void MW_StorePersistentVal ( persistentVal_t valueType,
uint8_t value )

Stores a value in General Purpose Registers (GPR) for preserving data between resets.

This function stores the specified value for the specified persistentVal_t in General Purpose Registers (GPR) in order to preserve data between non-POR/BOR device resets. Each value is stored in specific locations which is protected by a checksum. The stored values can be read using MW_GetPersistentVal.

Note

When a persistent value is updated, the new checksum is calculated from the intended GPR0 and GPR1 values held locally rather than from post-write GPR readback. This prevents corruption introduced during the GPR write from being incorporated into a matching checksum.

Note
This function can be used to clear single values by setting them to 0, while

MW_ClearPersistentVals is used to clear all values.

Note

An invalid value type is ignored and will set the internal invalid input flag, which is used in MW_IsPersistentValsCorrupt as part of checking for data validity.

Warning

This function verifies the stored checksum before writing any values. If the checksum has been corrupted, the function will return early to avoid calculating a new checksum. A corrupted checksum will be reported by MW_IsPersistentValsCorrupt.
